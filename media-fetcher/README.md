# メディア取得（個人用・自宅サーバー向け）

スマホのブラウザに動画のURL（YouTube、ニコニコ動画など）を貼ると、**自宅のマシン**が音声・動画を取得して変換し、完成したファイルをスマホにダウンロードできる Web アプリです。個人利用専用です。

- 取得と変換はすべてサーバー側で進みます。スマホの画面を消しても、ブラウザを閉じても止まりません。
- ジョブは SQLite（ファイル1つのデータベース）に保存され、サーバーを再起動しても続きから再開します。
- 取得エンジンの yt-dlp は毎日自動で更新され、更新で壊れたら自動で前の版に戻ります。
- 追加する前に「どのくらい時間がかかるか」「取得できない場合はその理由」が分かります。

> **最初に読んでください**：[7. 利用上の注意](#7-利用上の注意) に、利用規約・著作権・アカウント停止リスクをまとめています。

## 1. 自宅マシンでの起動手順

### 動かす場所について

**必ず自宅の回線につながったマシンで動かしてください。** VPS（Virtual Private Server＝レンタルの仮想サーバー）やクラウドのIPアドレスからのアクセスは、動画サイトにボットと判定されやすく、ほぼ確実に失敗します。

対応マシン：自宅のPC、ミニPC、Raspberry Pi（64ビット版OS＝arm64）。Raspberry Pi は 4 以降・メモリ 2GB 以上を推奨します。

### 必要なもの

- Docker と Docker Compose（`docker compose version` で確認できます）
- 空き容量（完成ファイルは既定で7日間残ります）

### 手順

```bash
cd media-fetcher

# 1. 設定ファイルを作る
cp .env.example .env

# 2. アクセス用トークン（合言葉）を作って .env の APP_TOKEN に書く
openssl rand -hex 24

# 3. .env を編集する（最低限 APP_TOKEN。できれば診断用URLも）
nano .env
chmod 600 .env        # ログイン情報を書くので、自分だけが読めるようにする

# 4. データ用フォルダーを作る（コンテナ内のユーザーと所有者を合わせる）
mkdir -p data/{downloads,config,cookies,ytdlp,work}
id -u; id -g          # 1000 以外なら .env の PUID / PGID をこの値にする

# 5. 起動
docker compose up -d --build

# 6. 起動時のチェック結果を見る
docker compose logs -f app
```

ログに `Deno 2.x.x を認識しました` と出れば準備完了です。`起動時チェック: Deno … が認識されていません` と出た場合は [6章](#6-動かなくなったときのチェックリスト) を見てください。`APP_TOKEN` が未設定・短すぎる場合は、安全のため起動しません。

同じマシンのブラウザで `http://127.0.0.1:8080` を開き、`APP_TOKEN` を入力して画面が出ることを確認します。**この時点ではスマホからは見えません**（わざと自分のマシンの中だけで待ち受けています）。スマホからは次の章の Tailscale 経由でつなぎます。

### .env の主な項目

| 項目 | 意味 | 既定値 |
|---|---|---|
| `APP_TOKEN` | アクセス用トークン（16文字以上・必須） | なし |
| `HEALTHCHECK_URL_YOUTUBE` / `_NICONICO` | 毎日の自己診断に使う公開動画のURL | 空（診断しない） |
| `LOGIN_MODE_YOUTUBE` / `_NICONICO` | ログインモード（4章） | `on_failure` / `always` |
| `NICONICO_USERNAME` / `NICONICO_PASSWORD` | ニコニコのID・パスワード | 空 |
| `MAX_CONCURRENCY` | 同時実行数（1 か 2） | 1 |
| `JOB_GAP_MIN_SECONDS` / `_MAX_` | ジョブ間のランダム待機 | 3〜8秒 |
| `MAX_RETRIES` / `RETRY_BASE_SECONDS` | 自動再試行の回数と最初の待ち時間 | 3回 / 30秒 |
| `AUTO_UPDATE` / `YTDLP_CHANNEL` | yt-dlp の自動更新と種類 | `true` / `stable` |
| `DEFAULT_DOWNLOAD_MBPS` / `DEFAULT_TRANSFER_MBPS` | 見積もりの初期値（5章） | 30 / 20 |
| `RETENTION_DAYS` | 完成ファイルを自動削除するまでの日数 | 7 |

診断用URLには、**誰でも再生できて、消えにくい動画**（公式チャンネルの古い動画など）を1本ずつ指定してください。

### 更新・停止

```bash
git pull && docker compose up -d --build   # アプリ本体を更新して作り直す
docker compose down                                   # 停止（data/ は残る）
```

## 2. Tailscale の導入とスマホからの接続

このアプリは **インターネットに公開しないでください。** ルーターのポート開放や、Cloudflare Tunnel・ngrok などでの公開はしないでください。代わりに Tailscale を使います。

Tailscale は、自分の機器どうしだけをつなぐ VPN（Virtual Private Network＝仮想専用線）です。自分のアカウントに登録した機器からしかアクセスできず、外出先のモバイル回線からでも自宅サーバーに届きます。

### 自宅マシン側

```bash
# 1. インストールしてログイン（表示されたURLをブラウザで開いて承認する）
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up

# 2. このアプリを Tailscale の中だけに HTTPS で出す
sudo tailscale serve --bg 8080

# 3. スマホで開くURLを確認する
tailscale serve status
```

`https://マシン名.テイルネット名.ts.net` というURLが表示されます。初回は Tailscale の管理画面（DNS）で **MagicDNS** と **HTTPS Certificates** を有効にするよう求められることがあります。

- `tailscale serve` は **自分の Tailscale ネットワーク内だけ** に出すコマンドです。
- 似た名前の **`tailscale funnel` はインターネット全体に公開するコマンドなので、使わないでください。**
- HTTPS（暗号化通信）にしているのは、ホーム画面への追加や共有メニュー（3章）がHTTPSでしか動かないためです。

### スマホ側

1. App Store / Google Play から **Tailscale** アプリを入れ、**自宅マシンと同じアカウント**でログインします。
2. アプリのスイッチをオン（接続）にします。
3. ブラウザで、上で確認した `https://….ts.net` のURLを開きます。
4. `APP_TOKEN` を入力します（1年以上は再入力不要です）。

外出先でも、Tailscale がオンになっていれば同じURLで使えます。

### 認証について

Tailscale に加えて、アプリ自体も `APP_TOKEN` による簡易認証を必須にしています。トークンを変えたいときは `.env` を書き換えて `docker compose up -d` し直すと、すべての端末でログインし直しになります。

## 3. ホーム画面への追加・共有メニュー・保存先

PWA（Progressive Web App＝ホーム画面に置いてアプリのように使える Web ページ）に対応しています。

### Android（Chrome）

- **ホーム画面に追加**：URLを開く → 右上の「︙」→「ホーム画面に追加」→「インストール」。
- **共有メニューから送る**：インストール後、YouTube アプリなどで「共有」→ 一覧から「**メディア取得**」を選ぶと、URLが入力された状態で開き、自動で「確認」まで進みます（Web Share Target という仕組みです）。一覧に出ないときは、いったんアンインストールして入れ直してください。
- **保存先**：「ダウンロード」を押すと Chrome のダウンロード機能が受け取ります。「Files（ファイル）」アプリの「ダウンロード」、または Chrome の「︙」→「ダウンロード」で確認できます。

### iPhone（Safari）

- **ホーム画面に追加**：Safari でURLを開く → 共有ボタン（□に↑）→「ホーム画面に追加」。
- **共有メニューから送る**：iPhone は Web Share Target に対応していないため、共有メニューに直接は出ません。代わりに、どちらかの方法を使ってください。
  - **コピーして貼り付け**：動画アプリで「リンクをコピー」→ このアプリを開いて「貼り付け」ボタン。
  - **ショートカットを作る**（共有メニューから1タップで送れます）：
    1. 「ショートカット」アプリで新規作成し、名前を「メディア取得へ送る」にする。
    2. 詳細（ⓘ）で「共有シートに表示」をオン、受け取る種類を「URL」と「テキスト」にする。
    3. アクション「URLエンコード」を追加し、入力を「ショートカットの入力」にする。
    4. アクション「URLを開く」を追加し、`https://あなたのURL.ts.net/?share=` の直後に手順3の結果（エンコード済みテキスト）を入れる。
- **保存先**：「ダウンロード」を押すと確認が出るので「ダウンロード」を選びます。「ファイル」アプリ →「ダウンロード」（iCloud Drive またはこの iPhone 内）に入ります。保存先は「設定」→「Safari」→「ダウンロード」で変えられます。
  - ホーム画面から開いた状態でダウンロードがうまく始まらないときは、Safari で同じURLを開いて「ダウンロード」を押してください。

### ダウンロードが途中で切れたら

ファイルの受信はOSのダウンロード機能に任せています。サーバーは HTTP Range（途中からの再開）に対応しているので、ブラウザのダウンロード一覧から「再開」できます。再開できないときは、もう一度「ダウンロード」を押してください（サーバー側のファイルは既定で7日間残ります）。

## 4. ログイン設定

年齢制限のある動画、ボット判定された場合、ニコニコ動画の一部の動画や高画質は、ログインしていないと取得できません。そのため、自分のアカウントでのログインに対応しています。

### ⚠ アカウント停止のリスク

**自分のアカウントのログイン情報を使ってダウンロードする行為は、各サイトの利用規約に反する場合があり、アカウントが警告・一時停止・永久停止されるおそれがあります。** 特に短時間に多数の動画を取得すると危険が高まります。

- 大切なアカウント（メインの Google アカウントなど）ではなく、**停止されても困らないアカウント**を使うことを強く勧めます。
- 必要がなければログインを使わない設定（「失敗時のみ使う」「使わない」）にしてください。
- 使うかどうかは自己責任で判断してください。

### ログインモード

管理画面（右上の「管理」→「ログイン設定」）で、サイトごとに選べます。

| モード | 動き | 既定 |
|---|---|---|
| 常に使う | 最初からログイン状態で取得する | ニコニコ動画 |
| 失敗時のみ使う | まず未ログインで試し、「ログイン必須」「年齢制限」「ボット判定」で失敗したときだけ、ログイン状態で自動的に1回再試行する | YouTube |
| 使わない | 常に未ログイン | — |

各ジョブがどちらで取得されたかは、一覧に「ログインあり／ログインなし」と表示されます。

### ニコニコ動画

次のどちらかで設定します（両方あるときは cookies.txt が優先されます）。

- **ID・パスワード**：`.env` の `NICONICO_USERNAME`（メールアドレス）と `NICONICO_PASSWORD` に書き、`docker compose up -d` で反映します。二段階認証を有効にしているアカウントでは使えないことがあるので、その場合は cookies.txt を使ってください。
- **cookies.txt**：下の YouTube と同じ手順で書き出し、管理画面の「ニコニコ動画」からアップロードします。

### YouTube（cookies.txt のみ）

YouTube は、パスワードや OAuth（外部アプリ連携の認可方式）でのログインが使えなくなっているため、ブラウザの Cookie（ログイン状態を記録した小さなデータ）をファイルに書き出して使います。

**長持ちしやすい書き出し方**（YouTube は、普段使いのブラウザで使われている Cookie を頻繁に入れ替えるため、ふつうに書き出すとすぐ無効になります）：

1. PCのブラウザで **シークレットウィンドウ（プライベートウィンドウ）** を新しく開く。
2. そのウィンドウで YouTube にログインする。
3. **同じタブ**で `https://www.youtube.com/robots.txt` を開く（余計な通信で Cookie が入れ替わるのを防ぐためです）。
4. Cookie 書き出し用の拡張機能（「Get cookies.txt LOCALLY」など。シークレットウィンドウでの実行を許可しておく）で、`youtube.com` の Cookie を **Netscape 形式の cookies.txt** として保存する。
5. **すぐにシークレットウィンドウを閉じる。**（ログアウトはしない。このログイン状態をブラウザ側で二度と使わないことで、Cookie が入れ替わらず長持ちします）

### アップロードと更新（スマホからできます）

1. 書き出した cookies.txt をスマホに送る（自分宛てのメール、クラウドストレージ、AirDrop など）。
2. アプリの「管理」→「ログイン設定」→ 対象サイトの「cookies.txt をアップロード」→ ファイルを選ぶ。
3. 状態が「有効」になれば完了です。差し替えるときも同じ手順です。

### 期限切れになったら

Cookie が無効になると、ジョブ一覧と管理画面の上部に **「Cookie期限切れ：再設定してください」** と表示されます。上の手順でもう一度書き出して、アップロードし直してください。

状態の判定方法：
- **YouTube**：ファイル内の有効期限に加え、取得時に yt-dlp が出す「Cookie が無効」という警告で判定します。
- **ニコニコ動画**：ファイル内の有効期限と、ログイン状態で取得して拒否されたかどうかで判定します。サーバー側で先に無効化された場合は、実際に取得に失敗するまで「有効」と表示されることがあります。

### ログイン情報の扱い

- cookies.txt は `data/cookies/` に **権限600**（自分だけが読める）で保存されます。
- Cookie の中身、パスワード、トークンは、画面・ログ・エラーの詳細には出しません（伏せ字にします）。
- `.env` も `chmod 600 .env` にしておいてください。

## 5. 所要時間の見積もりの見方と補正

### 表示の見方

URLを貼って「確認」を押すと、形式ごと（MP3 / WAV / MP4 各画質）に次のように表示されます。

```
MP4 720p                              約48MB
約3分（取得40秒・変換10秒・スマホへ2分） 目安 2分〜4分
取得形式：720p avc1 + mp4a
```

| 表示 | 意味 |
|---|---|
| 待ち | 先に並んでいるジョブが終わるまでの時間（あるときだけ表示） |
| 取得 | サーバーが動画サイトから素材を取ってくる時間 |
| 変換 | ffmpeg で MP3 / WAV にする、または映像と音声を結合する時間 |
| スマホへ | 完成ファイルをスマホにダウンロードする時間 |
| 目安 ○〜○ | ずれの幅。情報が少ないほど広くなります |

すべて **目安** です（そのため「約」を付けています）。実行中は実際の進み具合に合わせて「残り約○分」が更新されます。

注意書きが付く場合：

- **「H.264 で取得できないため再エンコードします」**：スマホで再生できる H.264 形式が無く、映像を作り直す必要があります。**Raspberry Pi では動画の長さの数倍かかることがあります。** 低い画質を選ぶと、H.264 が見つかって速く済むことがあります。
- **「サイズ情報が無いため、おおまかな推定です」**：サイト側がファイルサイズを教えてくれないため、一般的なビットレートで仮定しています。

### 計算式

```
総所要時間 ＝ 待ち時間 ＋ 取得時間 ＋ 変換時間 ＋ スマホへの転送時間

取得時間 ＝ 取得サイズ ÷ 取得速度 ＋ 固定オーバーヘッド（メタデータ取得・JSチャレンジ）
変換時間 ＝ 動画の長さ ÷ 変換速度倍率（再エンコードは画素数で補正）
転送時間 ＝ 完成サイズ ÷ スマホへの転送速度
```

- 取得サイズは、yt-dlp の `filesize` → `filesize_approx` → ビットレート×長さ、の順で使います。
- 完成サイズ：MP3＝ビットレート×長さ、WAV＝1411kbps（16bit/44.1kHz/ステレオ。元の音声が48kHzならその値）×長さ、MP4＝取得サイズとほぼ同じ。

### 自動で補正されるしくみ

- **取得速度・固定オーバーヘッド**：サイト別に、直近5件の実測の平均を使います。
- **変換速度倍率**：初回起動時に短いベンチマーク（MP3エンコード、WAV変換、MP4結合、H.264再エンコード）で初期値を作り、以後は実際の変換の実測で更新します。
- **スマホへの転送速度**：実際のダウンロードの実測（直近5件の平均）を使います。

最初の数回は `.env` の既定値で計算するため、ずれやすくなります。**5件ほど使うと実測に寄っていきます。**

### ずれが大きいときの補正方法

「管理」→「所要時間の見積もり」で、工程ごとの**平均誤差**と**傾向**（長めに出ている／短めに出ている）、現在使っている速度（「実測」か「既定値」か）を確認できます。

| 症状 | 対処 |
|---|---|
| まだ数件しか使っていない | そのまま使い続ける（自動で補正されます） |
| 「取得」が大きくずれる・既定値のまま | `.env` の `DEFAULT_DOWNLOAD_MBPS` を、サーバーの実際の下り速度に近い値にする |
| 「スマホへ転送」が大きくずれる | `.env` の `DEFAULT_TRANSFER_MBPS` を調整する。自宅Wi-Fiとモバイル回線で大きく変わるので、よく使う方に合わせる |
| 回線やルーターを変えた、引っ越した | 「回線速度の学習をリセット」を押す |
| サーバーのマシンを変えた・変換だけ大きくずれる | 「ベンチマークを再実行」を押す |
| 最初の1件目だけ毎回長い | 正常です（JSチャレンジの準備が初回だけ長くかかります） |

転送速度はサーバーが送り出した速さで測っているため、数MB以下の小さなファイルでは学習に使いません。

## 6. 動かなくなったときのチェックリスト

動画サイトは頻繁に仕様を変えるため、「昨日まで動いていたのに今日は動かない」ことが起こります。上から順に確認してください。

### ① 自己診断画面を見る（管理 → 自己診断）

毎日1回（既定は午前4時台）と起動時に、`.env` に設定した公開動画で「メタデータ取得」と「短い区間のダウンロード」を試しています。「今すぐ診断する」でその場でも実行できます。

| 表示 | 意味 | 対処 |
|---|---|---|
| yt-dlp ○ / Deno ○ / yt-dlp-ejs ○ / ffmpeg ○ | 環境は正常 | — |
| Deno × | JavaScript 実行環境が見つからない | ④へ |
| メタデータ取得 × | 動画の情報すら取れない | 原因候補の表示に従う。多くは②の更新で直る |
| メタデータ ○・ダウンロード × | 情報は取れるが本体が取れない | 一時ブロックか仕様変更。時間を置く→②の更新 |
| ログイン状態：期限切れ | Cookie が無効 | ⑤へ |
| 診断用URLが未設定 | `.env` に URL が無い | `HEALTHCHECK_URL_…` を設定して再起動 |

失敗時は「原因候補」を日本語で表示し、「詳細」に yt-dlp の元のメッセージを出します。

### ② yt-dlp を更新する（管理 → 取得エンジン → 更新）

「サイトの仕様変更の疑いがあります」と出たときは、まず更新してください。失敗したジョブに出る「**yt-dlpを更新して再試行**」ボタンでも同じことができます。

- 安定版（stable）で直らないときは「**nightly に切替**」を試してください。nightly は毎日作られる版で、仕様変更への対応が早く入ります。直ったら stable に戻してかまいません。

### ③ ロールバックする（管理 → 取得エンジン → ロールバック）

**更新した直後に壊れた**ときは、1つ前の版に戻せます。

- 自動更新では、更新後の自己診断が失敗し、前の版なら成功する場合に **自動で戻します**（更新履歴に「自動で戻しました」と残ります）。その版は「自己診断に失敗した版」として記録され、自動では再導入しません。
- 新旧どちらの版でも失敗する場合は、更新が原因ではない（回線断・一時ブロックなど）と判断して、新しい版のままにします。

### ④ Deno を確認する

YouTube は再生時に暗号化された JavaScript の課題（JSチャレンジ）を解かせます。これを解くために、外部の JavaScript 実行環境 **Deno** と、解決用スクリプト **yt-dlp-ejs** を使っています。どちらかが欠けると YouTube は取得できません。

```bash
docker compose exec app deno --version                     # バージョンが出ればOK
docker compose logs app | grep -i -e deno -e "起動時チェック"
docker compose build --no-cache && docker compose up -d     # 出ない・古いときは作り直す
```

「yt-dlp-ejs が見つかりません」と出たときは、②の「更新」で入り直します。

### ⑤ Cookie の期限切れを確認する

一覧や管理画面に「Cookie期限切れ：再設定してください」と出ていたら、[4章](#4-ログイン設定)の手順で cookies.txt を書き出し直してアップロードしてください。

### ⑥ ボット判定・一時ブロックのとき

「ボット判定、または一時的なアクセス制限を受けています」と出たら、**時間を置いて自動で再試行します**（既定は約10分後 → 20分後 → 40分後。次の再試行時刻が表示されます）。

- 続く場合は、**サーバーが自宅回線で動いているか**を確認してください。VPS・クラウドや、VPNサービスの出口を通していると判定されやすくなります（Tailscale はスマホとサーバーの間だけなので関係ありません。ただし Tailscale の「Exit Node」をサーバーで使っている場合は外してください）。
- 短時間に大量に追加しない、同時実行数を1件のままにする、数時間あけてから使う、のが有効です。

### ⑦ それでも直らないとき

```bash
docker compose logs --tail 200 app     # エラーの前後を確認
docker compose restart app             # 再起動（待機中のジョブは引き継がれます）
df -h                                  # 空き容量を確認
```

- 失敗したジョブの「詳細」に、yt-dlp / ffmpeg の元のエラーメッセージが出ています。yt-dlp の公式リポジトリの Issues で同じメッセージを探すと、対応状況が分かることがあります。
- yt-dlp の保存データを初期化したいときは、停止してから `data/ytdlp/` を空にすると、コンテナ同梱の版に戻ります。

### 取得できない理由の一覧

| 表示される理由 | 次にできること |
|---|---|
| 非公開、または削除済み | なし（取得できません） |
| 地域制限 | なし（取得できません） |
| ログインが必要（年齢制限など） | 「ログインして再試行」。Cookie 未設定なら設定画面へ |
| Cookie期限切れ | 「Cookieを再設定」 |
| 有料・メンバー限定・DRM 保護 | 取得対象外です（7章） |
| ライブ配信中・プレミア公開前 | 「配信終了後に再試行」 |
| ボット判定・一時ブロック | 自動再試行（次の時刻を表示） |
| サイトの仕様変更の疑い | 「yt-dlpを更新して再試行」 |
| 変換（ffmpeg）に失敗 | 詳細に ffmpeg ログの末尾を表示 |
| サーバーの空き容量不足 | 空き容量と必要容量を表示。不要なファイルを削除 |
| ネットワークエラー | 自動再試行。サーバーの回線を確認 |
| 不明なエラー | 詳細の元メッセージを確認 |

DRM は Digital Rights Management（コピー防止技術）の略です。

## 7. 利用上の注意

このアプリは **自分だけが、法律と各サイトの規約の範囲で使う** ためのものです。以下を守れない使い方はしないでください。

### 各サイトの利用規約

- YouTube やニコニコ動画などの利用規約は、サイトが用意した機能以外でのダウンロードを原則として認めていません。**規約に反する利用は、アカウントの停止やアクセス制限の対象になることがあります。** 使うかどうかは、各サイトの最新の規約を自分で確認したうえで判断してください。
- 自分が投稿した動画、権利者がダウンロードを許可している動画（クリエイティブ・コモンズなど）から使うのが安全です。

### 著作権法

- 日本の著作権法では、個人的に、または家庭内などの限られた範囲で使うための複製（**私的複製**）が一定の範囲で認められています。取得したファイルを**他人に渡す、再アップロードする、公開する、販売する、といった行為はこの範囲を超えます。**
- **違法にアップロードされたものだと知りながら**、音楽や映像をダウンロードすることは、私的な目的でも違法であり、有償で提供されている作品については刑事罰の対象になり得ます。
- **コピー防止技術（DRM などの技術的保護手段）を回避しての複製は、私的複製として認められません。** このアプリは DRM で保護された動画、有料・会員限定の動画を取得対象外とし、回避する機能を持ちません。
- 法律は改正されることがあり、ここに書いた内容は法的な助言ではありません。判断に迷うときは、文化庁の案内や専門家に確認してください。

### セキュリティ

- **インターネットに公開しないでください。** Tailscale 経由だけで使ってください（2章）。
- `APP_TOKEN`、`.env`、cookies.txt を他人に渡さないでください。cookies.txt は、あなたのアカウントにログインできる鍵そのものです。
- 入力できるのは `http://` / `https://` の公開アドレスだけです。ローカルアドレスやファイルのパスは拒否します。

### サイトへの負荷

同時実行は既定で1件、ジョブの間にはランダムな待機を入れ、失敗時は間隔を広げながら最大3回だけ再試行します。人が普通に使う程度の頻度に抑えるための設定なので、むやみに緩めないでください。

## 8. しくみ（開発者向け）

### 構成

- バックエンド：Python 3.12 + FastAPI + yt-dlp（`yt-dlp[default]` と `yt-dlp-ejs`）+ ffmpeg + Deno
- ジョブキュー：asyncio ワーカー + SQLite（外部サービス不要）
- フロント：素の HTML / CSS / JavaScript、PWA（manifest.json + Service Worker）

```
app/
  main.py            FastAPI 本体・認証・API・ファイル配信（Range 対応）・定期処理
  config.py          .env の読み込み
  db.py              SQLite（jobs / samples / settings / health / updates）
  security.py        URL検証・ファイル名サニタイズ・秘密情報の伏せ字
  error_rules.py     取得不可の理由の分類ルール（文言が変わったらここに追記）
  estimator.py       所要時間の見積もり（DBに依存しない純粋関数）
  formats.py         形式プリセットと「希望画質 → 次善」のフォーマット指定
  login.py           ログインモード・Cookie 管理・自動再試行ポリシー
  jobs.py            ワーカー・状態遷移・再試行・実測の学習
  ffmpeg.py          変換・進捗・ベンチマーク
  updater.py         yt-dlp の更新・チャンネル切替・ロールバック
  healthcheck.py     自己診断
  downloader/
    base.py          Downloader インターフェース
    adapters.py      サイト別アダプター（YouTube / ニコニコ / その他）
    ytdlp.py         yt-dlp 実装（子プロセスを起動する側）
    ytdlp_runner.py  子プロセス内で yt-dlp の Python API を呼ぶ
  static/            画面
tests/               pytest
scripts/field_test.py  実地試験（見積もりと実測を並べて表示）
```

### 設計上のポイント

- **yt-dlp は子プロセス内で Python API を呼びます。** バージョンごとに `data/ytdlp/versions/<版>/` へ `pip install --target` で導入し、子プロセスの `PYTHONPATH` を切り替えるだけで、再起動なしに更新・ロールバックできます。yt-dlp が異常終了しても本体は巻き込まれません。
- **取得と変換を分けています。** yt-dlp には素材の取得だけをさせ、結合・変換は自前で ffmpeg を呼びます。工程別の実測時間と ffmpeg ログの末尾を確実に取るためです。
- **取得処理は `Downloader` インターフェースの裏にあります。** 別のエンジンに差し替えるときは、`downloader/base.py` の `Downloader` を満たすクラスを作り、`adapters.py` の `SiteAdapter.downloader` に名前を指定して、`main.py` の `Core` で登録します。サイトを足すときは `adapters.py` に `SiteAdapter` を1つ追記します。
- **エラー分類は `error_rules.py` の `RULES` に集約しています。** 上から順に評価し、例外の種類とメッセージの正規表現で決めます。サイト側の文言が変わったら、該当ルールの `patterns` に1行足し、`tests/test_error_rules.py` の `CASES` に例を足してください。

### ジョブの状態

```
待機(queued) → 取得中(downloading) → 変換中(converting) → 完了(done)
                     └────────────┴→ 失敗(failed) → [再試行] → 待機
                     └────────────┴→ 待機（自動再試行待ち・再起動時の復元）
```

### テスト

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
pytest
```

ffmpeg が必要です。動画サイトにはアクセスしません（取得処理は差し替え用の偽 Downloader で検証します）。対象：URL検証、ジョブ状態遷移、エラー分類（各分類のメッセージ例）、ログインの自動再試行、所要時間の計算（サイズ不明時のフォールバック含む）、更新失敗時のロールバック、Range ダウンロード、日本語ファイル名、認証。

### 実地試験（実際のサイトで確認する）

自宅マシンでサーバーを起動した状態で実行すると、MP3 / WAV / MP4 を「ログインなし／あり」の両方で取得し、工程別の見積もりと実測を並べて表示します。

```bash
python3 scripts/field_test.py --token "$APP_TOKEN" \
  "https://www.youtube.com/watch?v=（公開動画）" \
  "https://www.nicovideo.jp/watch/（公開動画）" \
  --expect private_deleted="https://www.youtube.com/watch?v=（削除済みの動画）" \
  --expect login_required="https://www.youtube.com/watch?v=（年齢制限の動画）"
```

`--expect 分類=URL` は、そのURLが指定した分類で「取得不可」と表示されることを確認します。
